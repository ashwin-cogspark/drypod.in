│   ├─ story-*: OpenCode Go deepseek-v4.1-flash │                  │

**Daily loop**: timer fires → droid loads persona + story bible + state → 3 litellm calls (writer → editor → proof) → local gates (schema lint, NSFW classifier, rubric score) → publish script opens PR → CI builds + posts preview URL → human merges → deploy → RSS → votes accumulate → nightly sync writes trends back into factory state.

### Role/model architecture (writer/editor/proofreader — common or genre-specific?)

**Model routing is common; genre lives in prompts, not groups.**

- litellm has exactly **6 groups** = 3 roles × 2 content types: `story-writer`, `story-editor`, `story-proof`, and the `erotica-*` mirror. All three mainstream serials share them.
- A **persona** = genre-specific configuration layered on top: voice, seeds, chapter formula, AND the genre rubric the editor applies (a cultivation editor checks power-system consistency and arc pacing; the BBS editor checks system/economy rules and Tokyo-underworld continuity). Same editor *model*, genre-specific *rubric prompt*.
- Proofreader is fully common (grammar, continuity-with-state, formatting).
- Escape hatch: a persona MAY pin itself to a specific deployment inside a group (litellm supports model override per request) if a serial ever needs a different model — not needed at launch.

## Rollback

- Site: `git revert` chapter merges; redeploy previous wrangler version.
- Factory: timers stop cleanly; factory git history (private repo) = audit log.
- Votes: disable route = counts freeze; KV data untouched.
- litellm: remove group block, restart — council consumers unaffected (additive).
- BBS: canon preserved in vault archive (A13) + factory git; worst case the serial continues manually.
